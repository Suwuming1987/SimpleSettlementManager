# 界面与功能设计（M2 打磨阶段）

## 一、导航结构

从全息卡带 → 终端菜单（只有一项）→ **打开管理面板** → 面板首屏：

```
┌─────────────────────────────────────────────────────────┐
│  据点管理                                    [当前据点]  │
├─────────────────────────────────────────────────────────┤
│                                                         │
│     ▛▀▀▀▀▀▀▀▜   ▛▀▀▀▀▀▀▀▜   ▛▀▀▀▀▀▀▀▜                │
│     ▌ 总 览  ▐   ▌ 据 点  ▐   ▌ 居 民  ▐                │
│     ▙▄▄▄▄▄▄▄▟   ▙▄▄▄▄▄▄▄▟   ▙▄▄▄▄▄▄▄▟                │
│                                                         │
│     ▛▀▀▀▀▀▀▀▜   ▛▀▀▀▀▀▀▀▜                            │
│     ▌ 岗 位  ▐   ▌ 设 置  ▐                            │
│     ▙▄▄▄▄▄▄▄▟   ▙▄▄▄▄▄▄▄▟                            │
│                                                         │
│                                    [刷新]  [关闭]        │
└─────────────────────────────────────────────────────────┘
```

* 每个按钮进二级页面，二级页面左上角固定一个「‹ 返回」回到首屏。
* 首屏不放任何数据表格 —— 它只是导航。数据都在二级页里。
* 我把你原本的四项里**加了一项「岗位」**（理由见下），并建议不要把"批量操作"单列成一个入口。

## 二、五个页面各做什么

### 1. 总览
**目的**：一眼看清所有据点，找出需要处理的。

* 每个据点一行：名称 ・ 人口（无业）・ 食 ・ 水 ・ 电 ・ 防 ・ 床
* **状态标记**（决定性设计）：缺食 / 缺水 / 缺床 / 电不够 / 无业人数多 → 行首一个彩色点 + 悬浮说明
* 默认按「问题严重度」排序（缺东西的排前面），可切换为按名字
* 点一行 → 进「据点」页并选中该据点
* 底部：刷新 ・ 关闭

> 为什么不单做「需求 / 待办」页：需要关注的东西就是"某个据点缺什么"，
> 用状态标记 + 排序表达在同一屏里，比多一个页面更省点击。

### 2. 据点
**目的**：看一个据点的全貌，做批量操作。

* 上半：据点选择（所有据点列表）→ 选中后显示详情
* 详情内容：
  * 统计全量：人口（含机器人）/ 无业 / 幸福度 / 食 ・ 水 ・ 电 ・ 防 ・ 床（含缺额）
  * **床位视图**：床位对象数 / 已分配数 / 没有床的居民（列出名字）
  * **岗位视图**：所有工作岗位，含占用人姓名；空岗单独分组
  * 资源对象总数（作物、水源、发电机…）
* 批量操作：**一键填补空岗** ・ **解除全部岗位**（都带确认）
* **未加载的据点**：明细（居民/床位/岗位）显示为禁用状态，并提示「需要站到该据点范围内才能查看明细」——
  只显示汇总数值（这是原版机制决定的，见 DEVELOPMENT.md）

### 3. 居民
**目的**：以人为中心查看和操作（当前据点）。

* 筛选：全部 / 无业 / 在岗 / 队友；排序：状态 / 名字（已实现）
* 每人一行：名字 ・ 状态标签 ・ 岗位 ・ [解除] ・ [详情]
* 点「详情」→ 侧栏或子页，含：
  * 岗位明细（可多个）与**指派**入口（列出空岗供选）
  * **迁居**（列出其他据点；只对允许迁走的居民开放）
  * 三个原版开关：能否指挥 / 能否迁走 / 能否运输
  * 床位信息（有/无，若有则显示床名）
  * 队友标记说明（队友不参与自动派活）
* 底部：一键填补空岗 ・ 刷新 ・ 关闭

### 4. 岗位（新增建议）
**目的**：把"派活"这件事本身做成一个专门的工作台 —— 这是我们相对其他 mod 的唯一强项。

* 两栏配对视图：
  * 左：**无业居民**列表（可多选）
  * 右：**空闲岗位**列表（可多选）
  * 中间：点「配对」按钮 → 依次把选中的居民派到选中的岗位（数量不匹配时按较少的一方）
* 支持"点一下居民、点一下岗位"的单次配对（当前交互）
* 顶部显示统计：无业 N 人 / 空岗 M 个
* 这个页面顺带承担"排查"功能：一眼看出人多岗少还是岗多人少

### 5. 设置
**目的**：界面偏好与信息。

| 项 | 取值 | 说明 |
|---|---|---|
| 界面缩放 | 0.8 / 1.0 / 1.2 | 用 CSS `zoom`，实时生效 |
| 配色主题 | 哔哔绿 / 琥珀 / 冷蓝 | CSS 变量切换 |
| 默认排序 | 状态 / 名字 | 打开时用哪套 |
| 显示操作提示 | 开 / 关 | 是否在游戏里弹操作结果通知（通过 emit 告知 Papyrus） |
| 界面自检 | 一行状态 | 桥是否连通、数据是否收到 |
| 关于 | 版本、依赖（PrismaUI / WSFW）、**已知问题**（面板开着切换窗口后指针会冻住，按 Esc 即恢复 —— 这是 PrismaUI 与游戏的交互问题，NODE.LITE 同样存在） |

设置项存在**页面本地**（`localStorage`），不需要游戏侧存储。

## 三、贯穿全局的交互约定

1. **危险操作要确认**：「解除全部岗位」「一键填岗（会影响 N 人）」「迁居」都要二次确认弹层。
2. **状态色**：绿=正常 / 黄=需要注意（无业、缺额） / 蓝=队友 / 红=缺失（缺水缺食缺床）。
3. **返回**：二级页左上角固定「‹ 返回」；Esc 也可以关闭整个面板（PrismaUI 的处理）。
4. **未加载据点**的 UI 一律"看得见但点不动"，并给出原因 —— 不假装数据存在。
5. **所有操作即时反馈**：操作后立刻重新拉数据 + 面板内一行提示（"已把 X 派到 Y"）。
6. **键盘/手柄**：先做鼠标；PrismaUI 有手柄支持，之后可以补焦点顺序与 A/B 键。

## 四、数据协议需要补的字段

现有推送（行 + 竖线）已包含：据点汇总、居民（状态/岗位/三个开关）、空闲岗位。
需要补：

| 字段 | 用途 | 来源 |
|---|---|---|
| 每个居民的床位（有/无、床名） | 居民详情、床位视图 | `ActorOwnsBed` / 遍历 `GetBeds` |
| 岗位 → 占用人 | 据点页的岗位视图 | `GetAssignedActor`（已有） |
| 据点是否已加载 | 明细的可用性判断 | `Is3DLoaded()` |
| 缺额（食/水/床）与幸福度 | 总览的状态标记 | 已有的 Missing* / Happiness 索引 |
| 居民是否允许迁走 | 迁居入口的可用性 | `AllowMove`（已有，需展示） |

## 五、实施顺序建议

1. **首页 + 导航框架**（把现在的单屏拆成 首页 + 5 页，功能原地搬进去）—— 先把骨架立起来
2. **岗位页（配对工作台）** —— 我们的核心价值，最值得先做
3. **居民详情**（含迁居确认、床位信息）
4. **据点页**（含床位视图、批量操作确认）
5. **设置页**（缩放/主题/提示开关）
6. 视觉打磨（图标、状态色、悬停反馈、动效）
